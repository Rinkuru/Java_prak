# Описание сценариев системного тестирования

## 1. Общий подход

Системное тестирование web-интерфейса выполняется на уровне пользовательских сценариев.

Основной набор тестов реализован на:

- `Selenium`;
- `HtmlUnitDriver`;
- `TestNG`;
- `Spring Boot Test`.

Системными считаются сценарии, которые проходят через реальные страницы, ссылки, кнопки, формы и фильтры приложения.

Подготовка тестовых данных выполняется через DAO-хелперы, но сам проверяемый сценарий всегда выполняется через интерфейс.

Отдельно выделены дополнительные integration/HTTP-тесты для веток, которые невозможно честно воспроизвести через обычный UI:

- прямые POST с невозможными значениями;
- невалидные query-параметры, которые не отправляются интерфейсом;
- проверка технического HTTP-статуса `500`.

### NAV-01. Навигация с главной страницы в разделы
- **Use case:** 01, 10
- **Предусловия:** в системе есть хотя бы один человек и хотя бы одна компания с вакансией
- **Маршрут:** `P-01 -> P-02 -> P-01 -> P-06`
- **Шаги:**
  1. Открыть главную страницу.
  2. Перейти в раздел «Люди».
  3. Вернуться на главную страницу через верхнее меню.
  4. Перейти в раздел «Компании».
- **Ожидаемый результат:** открываются страницы списка людей и списка компаний, в них отображаются сохранённые данные.
- **Автотест:** `HomeAndNavigationSystemTests.homePageShouldNavigateToPeopleAndCompaniesSections`

## 3. Дополнительные integration-тесты вне честного UI

### INT-01. Прямой POST с недопустимым образованием человека
- **Причина выделения:** пользователь не может выбрать недопустимое образование через обычный `select`
- **Проверка:** сервер отклоняет прямой POST с произвольным значением и возвращает сообщение об ошибке
- **Автотест:** `WebHttpIntegrationTests.createPersonShouldRejectInvalidEducationOnDirectPost`

### INT-02. Подмена `companyId` при создании вакансии
- **Причина выделения:** в UI компания фиксируется карточкой компании
- **Проверка:** сервер отвергает подмену `companyId` в прямом POST и не создаёт вакансию
- **Автотест:** `WebHttpIntegrationTests.vacancyCreateShouldRejectCompanyBindingMismatchOnDirectPost`

### INT-03. Невалидные query-параметры фильтрации списка компаний
- **Причина выделения:** обычная форма не отправляет нечисловую зарплату и произвольный boolean
- **Проверка:** страница остаётся доступной, выводятся сообщения о некорректных фильтрах, корректная часть поиска всё равно работает
- **Автотест:** `WebHttpIntegrationTests.companiesListShouldReportInvalidVacancyFiltersOnDirectGet`

### INT-04. Невалидные query-параметры фильтрации вакансий компании
- **Причина выделения:** обычная форма не позволяет сформировать такой запрос
- **Проверка:** карточка компании открывается, пользователь получает сообщения о невалидных параметрах, валидная часть фильтра применяется
- **Автотест:** `WebHttpIntegrationTests.companyCardShouldReportInvalidVacancyFiltersOnDirectGet`

### INT-05. Невалидные query-параметры подбора вакансий для человека
- **Причина выделения:** UI-форма подбора не отправляет произвольные значения `sort` и `onlyActive`
- **Проверка:** страница остаётся доступной, выводятся сообщения о некорректных параметрах, применяются значения по умолчанию
- **Автотест:** `WebHttpIntegrationTests.personMatchesShouldReportInvalidQueryParamsOnDirectGet`

### INT-06. Явный `onlyActive=false` при подборе вакансий
- **Причина выделения:** текущая checkbox-форма не генерирует такой запрос как пользовательский сценарий
- **Проверка:** при прямом GET в результатах отображаются и открытые, и закрытые вакансии, порядок соответствует выбранной сортировке
- **Автотест:** `WebHttpIntegrationTests.personMatchesShouldAllowClosedVacanciesOnDirectGetWhenExplicitlyRequested`

### INT-07. Невалидные query-параметры подбора резюме для вакансии
- **Причина выделения:** UI-форма подбора не отправляет произвольные значения `sort` и `onlyLookingForJob`
- **Проверка:** страница остаётся доступной, выводятся сообщения о некорректных параметрах
- **Автотест:** `WebHttpIntegrationTests.vacancyMatchesShouldReportInvalidQueryParamsOnDirectGet`

### INT-08. Явный `onlyLookingForJob=false` при подборе резюме
- **Причина выделения:** текущая checkbox-форма не генерирует такой запрос как честный UI-сценарий
- **Проверка:** при прямом GET в результатах подбора появляются люди со статусом «не ищет работу», порядок соответствует выбранной сортировке
- **Автотест:** `WebHttpIntegrationTests.vacancyMatchesShouldAllowPeopleNotLookingForJobOnDirectGetWhenExplicitlyRequested`

### INT-09. Friendly error page и статус `500`
- **Причина выделения:** это техническая проверка не обычного пользовательского сценария, а обработки непредвиденного исключения
- **Проверка:** по специальному тестовому маршруту сервер возвращает статус `500` и пользовательскую страницу ошибки без stack trace
- **Автотест:** `WebHttpIntegrationTests.unexpectedErrorsShouldRenderFriendlyPageWith500Status`
