# Отчёт по третьему этапу

## 1. Назначение приложения

Приложение реализует web-интерфейс по теме **«Кадровое агентство»**.

Предметная область:

- люди и их резюме;
- история работы кандидатов;
- компании;
- вакансии компаний;
- подбор подходящих вакансий для человека и подходящих резюме для вакансии.

Система поддерживает просмотр, поиск, фильтрацию, добавление, редактирование и удаление данных, а также обработку пользовательских ошибок и системное тестирование интерфейса.

## 2. Используемый web-стек и архитектура

Web-часть проекта реализована на стеке:

- `Spring Boot`;
- `Spring MVC controllers`;
- `Thymeleaf`;
- встроенный servlet container Spring Boot;
- `Spring Validation`;
- `Selenium/HtmlUnit` для системных тестов.

Основные зависимости web-этапа подключены в `build.gradle`:

- `spring-boot-starter-webmvc`;
- `spring-boot-starter-thymeleaf`;
- `spring-boot-starter-validation`;
- Selenium и HtmlUnit-драйвер для системных тестов.

Запуск приложения начинается из класса `JavaPrakApplication`, где вызывается `SpringApplication.run(...)`.

Основная конфигурация web-слоя задаётся в `src/main/resources/application.properties`:

- подключение к PostgreSQL;
- `spring.jpa.hibernate.ddl-auto=validate`;
- `spring.jpa.open-in-view=false`;
- `spring.thymeleaf.cache=false`;
- `server.port=8080`.

Отдельного `web.xml` в проекте нет. Роль конфигурации основного сервлета выполняет автоконфигурация Spring Boot: при наличии `spring-boot-starter-webmvc` приложение поднимает встроенный web-сервер и регистрирует `DispatcherServlet` автоматически.

## 3. Реализованные страницы и навигация

В приложении реализованы страницы:

- `P-01` — главная страница;
- `P-02` — список людей;
- `P-03` — карточка человека;
- `P-04` — формы создания и редактирования человека;
- `P-05` — формы создания и редактирования записи о работе;
- `P-06` — список компаний;
- `P-07` — карточка компании;
- `P-08` — формы создания и редактирования компании;
- `P-09` — карточка вакансии;
- `P-10` — формы создания и редактирования вакансии;
- `P-11` — результаты подбора.

Шаблоны находятся в `src/main/resources/templates` и организованы по разделам:

- `home.html`;
- `people/*`;
- `companies/*`;
- `vacancies/*`;
- `work-experiences/*`;
- `matching/results.html`;
- `error/500.html`;
- `fragments/layout.html`.

Общая навигация построена вокруг списков и карточек сущностей:

- с главной страницы пользователь переходит в разделы «Люди» и «Компании»;
- из списков открываются карточки сущностей;
- из карточек открываются формы создания, редактирования и связанные сценарии;
- из карточки человека и карточки вакансии открывается подбор;
- все формы содержат возврат на родительскую страницу.

## 4. Контроллеры и обработка запросов

В пакете `ru.msu.cmc.java_prak.web.controller` реализованы контроллеры:

- `HomeController` — главная страница;
- `PersonController` — список людей, карточка человека, создание, редактирование и удаление человека, фильтрация списка;
- `WorkExperienceController` — создание, редактирование и удаление записей истории работы;
- `CompanyController` — список компаний, карточка компании, создание, редактирование и удаление компании, фильтрация списка компаний и вакансий;
- `VacancyController` — создание, просмотр, редактирование, удаление, закрытие и переоткрытие вакансий;
- `MatchingController` — подбор вакансий для человека и подбор резюме для вакансии;
- `GlobalErrorControllerAdvice` — обработка непредвиденных исключений и вывод пользовательской страницы ошибки;
- `TestPageController` — служебная тестовая страница и маршрут для проверки friendly error page.

Контроллеры работают через Spring MVC-аннотации `@Controller`, `@RequestMapping`, `@GetMapping`, `@PostMapping`, принимают данные форм, подготавливают модель и возвращают имена Thymeleaf-шаблонов.

## 5. Валидация, сообщения и обработка ошибок

На этапе web-интерфейса была реализована обработка пользовательских ошибок и сообщений:

- проверки обязательных полей в формах человека, компании, вакансии и истории работы;
- проверки длины строковых полей;
- проверки корректности зарплаты;
- проверки дат и отсутствия пересечений в истории работы;
- проверки справочных значений образования;
- проверки согласованности данных человека, который ищет работу;
- проверки бизнес-ограничений удаления компании и согласованности компании при создании вакансии;
- проверки параметров фильтрации и сортировки на страницах списков и подбора.

Пользовательские сообщения делятся на три группы:

- `successMessage` — успешное создание, обновление, удаление, закрытие и переоткрытие;
- `errorMessage` — ожидаемые ошибки пользователя и бизнес-ограничения;
- field-level ошибки валидации внутри форм.

Для непредвиденных исключений реализована отдельная страница `error/500.html`. Она используется через `GlobalErrorControllerAdvice` и не показывает пользователю stack trace.

## 6. Поиск, фильтрация и подбор

На web-страницах реализованы основные сценарии предметной области:

- поиск резюме по образованию;
- поиск резюме по зарплате;
- поиск резюме по компаниям из опыта;
- поиск резюме по должностям из опыта;
- комбинированные фильтры и сортировка списка людей;
- поиск компаний по названию;
- отбор компаний с открытыми вакансиями;
- фильтрация компаний по параметрам вакансий;
- фильтрация вакансий компании по должности, зарплате и статусу;
- переход из карточки вакансии к поиску вакансий той же должности;
- подбор вакансий для человека;
- подбор резюме для вакансии;
- сортировка результатов подбора;
- скрытие закрытых вакансий и скрытие людей, не ищущих работу;
- специальные информационные состояния при неполных данных для подбора.

## 7. Системные тесты

Системные тесты размещены в `src/test/java/ru/msu/cmc/java_prak/web`.

Набор Selenium/HtmlUnit-тестов разделён по подсистемам:

- `HomeAndNavigationSystemTests`;
- `PeopleSystemTests`;
- `WorkExperienceSystemTests`;
- `CompaniesSystemTests`;
- `VacanciesSystemTests`;
- `MatchingSystemTests`.

Общие Selenium-хелперы вынесены в `AbstractSeleniumSystemTest`, а подготовка данных — в `AbstractWebTestSupport`.

Системные тесты выполняют действия через интерфейс:

- переходы по ссылкам;
- нажатия кнопок;
- отправку форм;
- фильтрацию и сортировку через видимые элементы страниц.

Отдельно реализованы `WebHttpIntegrationTests` для веток, которые нельзя честно воспроизвести через UI:

- прямые POST с невозможными значениями;
- невалидные query-параметры, которые не отправляются обычной формой;
- проверка friendly error page и HTTP-статуса `500`.

Матрица покрытия use case хранится в `src/test/resources/readme-use-case-matrix.md`.
Отдельное текстовое описание сценариев системного тестирования подготовлено в документе `SYSTEM TEST SCENARIOS.md`.

## 8. Сборка, запуск и Ant

Файл `sql/build.xml` дополнен задачами для полного цикла работы с приложением.

Для запуска `ant -f sql/build.xml`

Поддерживаются цели:

- `compile`;
- `test-compile`;
- `test`;
- `build`;
- `deploy`;
- `status`;
- `undeploy`;
- `full-run`;
- `full-reset-run`.

Назначение задач:

- `compile` — сборка основного кода через Gradle `classes`;
- `test-compile` — сборка тестового кода через Gradle `testClasses`;
- `test` — запуск всех тестов на H2;
- `build` — сборка runnable Spring Boot jar;
- `deploy` — подготовка PostgreSQL в Docker, сборка jar и запуск приложения;
- `status` — проверка состояния приложения;
- `undeploy` — остановка приложения;
- `full-run` — полный прогон `clean + test + deploy`.

Таким образом, Ant используется как единая точка входа для сборки, тестирования и локального развёртывания приложения.
